# OpenARM 机械臂出厂质检工作台 V4 Spec

更新时间：2026-04-27  
状态：Proposed

## 1. 目的

V4 的目标不是继续把工作台停留在“电机配置 + 通信盘点”层，而是将其提升为一套可支撑机械臂出厂交付的质检工站。

V4 重点补齐以下能力：

- 零位校准流程
- 官方 Demo / 官方测试程序验证
- 单电机级测试报告
- 单电机唯一序列号管理
- 整机 CN 管理
- 零位校准工件与可追溯记录
- 出厂文件包自动生成

一句话定义：

`V4 = OpenARM 机械臂从“可通信”走向“可出厂”的工站版本`

## 2. 当前状态与缺口

基于当前仓库与工作台能力，已完成：

- 单电机 ID / 波特率 / 模式配置
- 整臂总线盘点
- 整臂链路测试
- 参数探测与问题扫描
- 出厂说明文档基础版

当前尚未形成完整出厂闭环的关键缺口：

1. 缺少正式的零位校准任务流。
2. 缺少官方 Demo / 官方脚本验证任务流。
3. 缺少以“单电机”为单位的 SN 与测试报告归档。
4. 缺少以“整机”为单位的 CN 与交付包归档。
5. 缺少出厂质检通过标准与签核状态。

## 3. V4 产品目标

V4 必须支持以下四类结果：

1. `单电机可追溯`
   每个关节电机必须有测试记录、参数记录和问题历史；内部电机追溯号为可选记录项，不进入正式整机 PDF 结论。

2. `整机可追溯`
   每台机械臂必须有唯一 CN，并能关联左右臂、关节编号、可选内部电机追溯号、零位记录和验收报告。

3. `出厂可证明`
   工作台能够导出完整质检包，而不是只给一份文字说明。

4. `复检可复现`
   客户返修或售后时，可按整机 CN、关节编号和可选内部电机追溯号回溯历史测试记录。

## 4. 出厂分级定义

V4 将出厂准备度拆为四个等级：

### 4.1 Level A: 基础通信可用

包含：

- CAN ID 配置完成
- `CAN 2.0 / 1 Mbps` 统一
- 整臂在线盘点通过
- 链路测试通过

说明：

- 这是当前工作台已基本具备的层级。

### 4.2 Level B: 参数与配置可追溯

包含：

- `CTRL_MODE / TIMEOUT / can_br / Gr / KT_Value / PMAX / VMAX / TMAX` 回读稳定
- 参数一致性矩阵通过
- 单电机参数快照归档

### 4.3 Level C: 校准与功能可交付

包含：

- 零位校准完成
- 零位保存后复核通过
- 单关节功能测试通过
- 夹爪专项测试通过
- 官方 Demo / 官方测试程序通过

### 4.4 Level D: 完整出厂质检

包含：

- 整机 CN 建档
- 可选内部电机追溯号 / 关节绑定
- 出厂文件包生成
- 质检结论签核

## 5. 新增任务模型

V4 在 V3 基础上新增以下任务。

### 5.1 `motor_serial_bind`

目标：

- 给单颗电机绑定唯一 SN
- 记录型号、关节归属、固件版本、出厂参数版本

输出：

- `motor_identity.json`

### 5.2 `motor_qc_report`

目标：

- 对单颗电机生成完整测试报告

至少包含：

- 基本身份信息
- 当前参数快照
- 通信结果
- 链路测试结果
- 微动测试结果
- 零位结果
- 备注与问题

### 5.3 `arm_cn_bind`

目标：

- 给整台机械臂生成唯一 CN
- 绑定左右臂、关节编号及可选内部电机追溯号

输出：

- `arm_identity.json`

### 5.4 `arm_zero_guided`

目标：

- 按 OpenARM 官方流程引导零位校准

要求：

- 支持左右臂分开校准
- 支持校准前姿态确认
- 支持校准后保存与断电复核提示

输出：

- `zero_calibration.json`
- `zero_pose_checklist.json`

### 5.5 `arm_demo_validation`

目标：

- 运行官方 Demo / 官方测试程序
- 记录运行结果与日志路径

要求：

- 至少支持“低风险模式”
- 明确区分：
  - `官方通信测试`
  - `官方 demo 运行`
  - `Follower 功能验证`

输出：

- `demo_validation.json`
- `demo_logs/`

### 5.6 `gripper_calibration_check`

目标：

- 检查夹爪开合位置与程序定义是否一致
- 排查“持续发力 / 嗡嗡响 / 发热 / 位置漂移”

输出：

- `gripper_check.json`

### 5.7 `shipment_qc_bundle`

目标：

- 自动汇总整机全部工件
- 生成完整出厂包

输出：

- `qc_report.html`
- `qc_report.json`
- `motor_reports/`
- `zero_files/`
- `demo_logs/`
- `delivery_bundle.zip`

## 6. 数据模型

### 6.1 电机序列号 `SN`

每颗电机必须有唯一 `motor_sn`。

最少字段：

- `motor_sn`
- `motor_type`
- `vendor`
- `hw_revision`
- `fw_version`
- `received_date`
- `installed_joint`
- `arm_cn`
- `esc_id`
- `mst_id`
- `status`

### 6.2 整机编号 `CN`

每台机械臂必须有唯一 `arm_cn`。

最少字段：

- `arm_cn`
- `arm_type`
- `bom_profile`
- `left_arm_installed`
- `right_arm_installed`
- `created_at`
- `qc_status`
- `delivery_status`

### 6.3 关节绑定表

每台机械臂必须保存：

- `R-J1 ~ R-J8`
- `L-J1 ~ L-J8`

与以下字段的映射：

- `motor_sn`
- `esc_id`
- `mst_id`
- `motor_type`
- `fw_version`

## 7. 零位校准任务规范

### 7.1 任务前提

零位任务只能在以下条件满足时开放：

- 整臂通信扫描通过
- 无重复 ID
- 无缺失关节
- 无明显 fault
- 操作者已完成人工姿态摆位

### 7.2 流程

1. 选择 `左臂 / 右臂 / 整机`
2. 显示官方推荐零位姿态图与确认项
3. 操作者勾选“机械姿态已对齐”
4. 进入零位校准
5. 保存零位
6. 生成零位记录文件
7. 提示断电重上电复核

### 7.3 风险要求

- 默认高风险动作必须二次确认
- 页面明确提示“会自动大幅运动”
- 必须支持急停确认清单

## 8. 官方 Demo / 官方测试程序验证

V4 不应只做内部微动测试，还应支持官方验证链路。

### 8.1 最小验证范围

- OpenARM 官方通信测试脚本
- OpenARM 官方 Demo 程序
- Follower 联调准备检查

### 8.2 结果记录

至少记录：

- 启动命令
- 运行时长
- 是否正常退出
- 错误码 / 异常日志
- 人工观察结果

## 9. 单电机测试报告

每颗电机的测试报告必须可以单独导出。

建议命名：

- `motor_report_{motor_sn}.html`
- `motor_report_{motor_sn}.json`

最少包含：

- `motor_sn`
- `arm_cn`
- `joint_name`
- `motor_type`
- `esc_id / mst_id`
- 参数快照
- 链路测试结果
- 微动测试结果
- 零位结果
- 最终判定

## 10. 整机出厂文件包

建议生成以下交付包：

1. `硬件装配完成确认书`
2. `整机 QC Report`
3. `零位校准记录`
4. `官方 Demo / 测试验证记录`
5. `左右臂关节与内部电机追溯号对照表（可选）`
6. `软件 / 固件版本清单`
7. `安全注意事项`
8. `质保与技术支持说明`

## 11. UI 结构扩展

V4 顶层主 Tab 建议扩展为：

- `任务`
- `连接`
- `识别`
- `执行`
- `校准`
- `监测`
- `报告`
- `出厂包`

其中：

### `校准`

负责：

- 零位校准
- 夹爪校准
- 零位记录与复核

### `出厂包`

负责：

- CN / SN 录入
- 绑定关系确认
- 导出交付文件包

## 12. 验收标准

V4 的最小验收标准应分为两层：

### 12.1 软件功能验收

- 能创建并保存 `arm_cn`
- 能创建并保存 `motor_sn`
- 能生成电机级报告
- 能生成整机级报告
- 能保存零位校准工件
- 能保存 Demo 验证工件

### 12.2 工位流程验收

- 单电机从识别到报告闭环可跑通
- 整机从盘点到零位到出厂包闭环可跑通
- 断电后重新进入工作台仍可按 `CN / SN` 找回历史记录

## 13. 实施阶段建议

### P0

- 明确 `SN / CN` 数据模型
- 明确工件目录结构
- 明确报告模板

### P1

- 实现 `motor_serial_bind`
- 实现 `arm_cn_bind`
- 实现单电机报告导出

### P2

- 实现 `arm_zero_guided`
- 实现 `zero_calibration.json`

### P3

- 实现 `arm_demo_validation`
- 实现 `demo_logs/`

### P4

- 实现 `shipment_qc_bundle`
- 自动打包完整交付文件

## 14. 当前建议

结合你现在的现状，最务实的下一步顺序建议是：

1. 先补 `SN / CN` 与报告追溯结构。
2. 再补零位校准任务流。
3. 再补官方 Demo / 官方测试程序验证。
4. 最后再做完整出厂包自动生成。

这样可以在不打断当前工位可用性的前提下，逐步从“通信工站”升级到“出厂质检工站”。
